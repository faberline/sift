# ADR 0002: DDD phase P2, first batch

- **Status:** Accepted. The four rounds below were approved together on
  2026-09-30 and are applied on `refactor/ddd-p2`.
- **Date:** 2026-09-30
- **Applies to:** everything under `src/` and `tests/`, and the `docs/` pages
  that describe them. Behaviour, the CLI and persisted bytes do not change.

## Context

P1 ([ADR 0001](0001-ddd-layout.md)) moved Sift into the DDD layout without
changing behaviour. It recorded every rule break it did not fix as a
`ddd.toml` exception, 78 in all. Two files stayed C1 warnings because each
holds one function above 400 lines (E9). P2 removes those exceptions and
warnings, each change approved on its own. This ADR records the first batch
and the decisions made for it.

ADR 0001 said other repos import Sift by its module paths. None does. Only
Sift's own binary and integration tests use them, so the compatibility
facades could go once those callers moved.

## Decision

### Scope

Four rounds, in this order:

1. **Structure.** Delete the dead batch ingest code (X1, X2). Remove the
   compatibility facades. Move cold-query replay from the archive to the
   query context. Rename `JournalState` to `ResidentWindow`. Split the two
   E9 functions.
2. **Domain errors (E6).** The domain layers and the shared kernel use
   thiserror instead of `anyhow`.
3. **Domain clock reads (E7).** Domain code takes `now` as an argument.
4. **Small cleanups.** X3–X6 and X10: one single-signal check, one default
   query limit, one UTF-8 truncation, one SHA-256 hex helper and one
   manifest-hash check.

Each of these is left for a later batch, planned and approved on its own:

- the journal–archive and other ports
- `ServiceState` accessors
- a `Clock` port
- X7–X9
- approving or removing each remaining B2 crate
- the other B3 layer fixes

### Rules every commit follows

- **Behaviour is unchanged.**
  - Error Display text stays the same.
  - `sift spec` with the OpenAPI document, `sift --help` and every
    subcommand's `--help` stay byte-identical to `main`.
  - Deleting the dead batch code also deleted that code's unit tests.
- **`ddd.toml` only shrinks.**
  - No commit adds an exception.
  - A new file inherits an exception only through `[[renames]]`, from the
    file it replaces within the same exception.
  - A commit that fixes a break deletes the break's entry.
- **Each commit passes every check.** It builds with no warnings, adds no
  clippy findings, passes the full test suite and passes
  `rust_arch_contract.py check --strict`.

### Public paths

- **Where public items live.**
  - Every context is a `pub mod`, and its module file re-exports the
    context's public items, so a caller writes `sift::<context>::Item`.
  - The layers stay `pub(crate)`.
  - The crate root keeps its re-exports, including the whole event model.
    The model is defined in the private shared kernel.
- **Nothing is dropped.** When a facade goes, every item it exported stays
  public. Dropping an item nothing uses would be deleting code, which is an
  X item.
- **Renamed re-exports.** A name that would not say what it is at the
  context root gets a prefix, with `as`, when it is re-exported:
  - `mcp_http_router`, `serve_mcp_stdio` and `mcp_tool_names`
  - `run_operator`
  - `serve_otlp_grpc` and `serve_otlp_grpc_proxy`
  - `decode_otlp`, `encode_otlp_response` and `normalize_otlp_payload`
- **No protobuf re-exports.** Third-party protobuf types are not
  re-exported. Callers use `transport_otlp::proto` and
  `metrics_remote_write::proto`, which are already normal dependencies.
- **Imports inside the crate.** Code inside the crate imports each item from
  the module that defines it, not from a context root.

[architecture.md](../architecture.md#public-api) lists every old path and
what replaced it.

### Splitting the two long functions (E9)

- **Mechanical extraction.**
  - Each block moves into a function unchanged.
  - State that a block changes is passed by `&mut`.
  - Nothing is merged or de-duplicated in the same commit.
  - No test is added first.
- **Checking the lifecycle worker.** Its replicated branch has no test.
  Instead, a script finds every moved line in the original function, in the
  same order.

### Domain errors (E6)

- **One enum per module.** Each domain module gets one error enum. It goes in
  the same file or in a sibling `*_error.rs`.
- **Display text stays the same.**
  - `.context("X")` around another error becomes `#[error("X")]` with a
    `#[source]` field, not `"X: {0}"`. Otherwise `{:#}` would print the cause
    twice.
  - `.context` on an `Option` becomes a plain variant.
  - A bare `?` becomes `#[error(transparent)]`.
- **Other layers keep `anyhow`.** The application and infrastructure layers
  keep it, and `?` converts.

### Domain clock reads (E7)

- **The rule.** A domain function takes `now` as an argument, and a caller
  outside the domain reads the clock. This is the shape
  `retention_rejection_at` already has.
- **No `Clock` port.** There is none in this batch.
- **Other layers.** Application and infrastructure code keeps its own
  `Utc::now` calls.

## Consequences

- There are no compatibility facades. Every public path is a crate-root
  re-export or `sift::<context>::Item`.
- The planned count is 46 exceptions after the fourth round, and no C1
  warnings.
- The remaining exceptions are the next batches' backlog. Each exception's
  reason still says what removes it.

## Results

### Round 1: structure

Eleven commits on `refactor/ddd-p2`.

- **Exceptions:** 78 → 57.
  - B1 16 → 0. The dead batch code took two facades with it, and the other
    14 facades are gone.
  - B3 21 → 19: the dead batch handler's use of the infrastructure, and the
    lifecycle worker's use of the domain from the interfaces layer.
  - B4 19 → 16: the archive's uses of the query and projection contexts in
    cold-query replay, which now lives in query.
  - B2 stays at 22 until the second and third rounds.
- **File size:** no C1 warning is left.
- **Tests:** 222 passed and 24 ignored, one fewer than `main`. The deleted
  GCP normalizer took one unit test with it; its two event-ID tests moved to
  the shared kernel.
- **Where it differs from the plan:**
  - Retention expiration became three files, not two. With the segment
    rewrite in it, `retention_pass.rs` would have been 423 lines.
  - The lifecycle worker check compares tokens rather than lines, so it also
    catches a change inside a line. It also checks that each extracted call
    passes every parameter the old local of the same name.
  - Only `lifecycle_checkpoint.rs` inherits the journal-domain exception;
    `lifecycle_tick.rs` needs none.
  - ADR 0001 still lists the `ResidentWindow` rename as P2 work. An ADR
    records a decision as it was made, so ADR 0001 is unchanged.
- **Left as found:** `aw.toml` and `external-contracts/` still describe the
  removed `/v1/events` route, and `docs/operations/structured-stdout.md`
  still mentions the Cloud Logging input. None of these is in this batch's
  scope.

### Round 2: domain errors

Eight commits, one per context, in the planned order: the shared kernel,
operations, collector, query, projection, journal, ingest and archive.

- **Exceptions:** 57 → 49. The eight B2 `anyhow` entries are gone, so B2
  goes from 22 to 14. No domain layer and not the shared kernel uses
  `anyhow`.
- **Text:** for each commit, a script collected every error message in the
  context's domain files before and after. Every message is still there.
- **Tests:** 222 passed and 24 ignored after every commit, the same as
  round 1.
- **Where it differs from the plan:**
  - **One failure, one struct.** A module with a single failure has a unit
    or newtype struct instead of a one-variant enum: `InvalidNamespace`,
    `InvalidQueryId`, and the journal's `ContentDigestError` and
    `InvalidAcknowledgedAt`.
  - **Shared types.** Two modules return another module's type, because
    every failure they report is already one of its variants:
    `filter_evaluator` returns `filter_expression`'s `FilterError`, and
    `metric_aggregation` returns `metric`'s `MetricError`.
  - **Repeated messages.** A message that several call sites repeated is one
    variant now. For query and journal the script compared the distinct
    messages, not the count of each.
  - **Boxed causes.** An error that wraps its own type holds it in a `Box`
    as `#[source]`: the governance policy set, and a bad metric query time.
    The archive manifest validator wraps the `anyhow` error from
    `service_backup`'s `GcsSink::from_exact_uri` as a boxed
    `std::error::Error`, so the domain does not name `anyhow`.
  - **`BlobHashSet`.** The trait has an unbounded `type Error`. The restore,
    which uses it, requires `anyhow::Error: From<H::Error>`, which is what
    `?` needs, instead of the planned `Into<anyhow::Error>`.

### Round 3: domain clock reads

One commit.

- **Exceptions:** 49 → 46. The three B2 `chrono::Utc::now` entries are gone,
  so B2 goes from 14 to 11. No domain layer and not the shared kernel reads
  the clock.
- **What changed:**
  - `OperationalEventV2::for_project_at` takes the time. `for_project` and
    `new` pass it `Utc::now()` and are in `src/app/system_clock.rs`. The
    OTLP, remote-write and service-log mappers call `for_project_at` with
    `Utc::now()`.
  - `cold_query_requested_at` takes the time, and the query use case passes
    `Utc::now()`.
  - `SiftCommandV1::append_events_now` is gone. The two diagnostics encoders
    call `append_events_at` with `Utc::now()`.
- **Tests:** 222 passed and 24 ignored, the same as round 2.
- **Where it differs from the plan:** none.

### Round 4: small cleanups

Five commits, in the order X4, X6, X5, X10, X3.

- **Exceptions:** 46, unchanged. No cleanup needed a new entry, and none
  removed one.
- **What changed:**
  - **X4.** `shared_kernel::query_limit` holds the default query limit of
    100. The query API and the log, metric and trace queries use it as their
    serde default.
  - **X6.** `shared_kernel::sha256_hex` is the lowercase hex SHA-256 digest.
    The archive's and the metric series' private helpers are gone, and the
    journal, node, query and projections call it for whole-buffer hashes.
  - **X5.** `shared_kernel::utf8_truncate` cuts text to a byte budget on a
    character boundary. The governance policy, the collector's quarantine
    and the two API clients call it.
  - **X10.** `fetch_checkpoint_manifest` fetches, checks, decodes and
    validates an archive checkpoint's manifest, for both staging and
    restore.
  - **X3.** `ensure_single_signal` takes the batch's name. The ingest
    append, the durable append and the Raft append policy share it.
- **Text:** every error message is the same, and the OpenAPI document is
  byte-identical.
- **Tests:** 225 passed and 24 ignored. The three new tests are the unit
  tests of `truncate_utf8`.
- **Where it differs from the plan:** the check that the four truncation
  copies agree ran as a scratch harness on 90 cases, not as a test in the
  repository, because the copies were private to four modules.
